# feedback 表單欄位字典（codebook）

> 給 AI agent 與未來的自己看。把回應 Sheet 匯出成 CSV 時，一併附上這份檔案。
> 表單：小老師助手 — 意見回饋
> 版本：v1（2026-08-17）

---

## 一、資料結構

- **每一列 = 一筆使用者回饋，一筆回饋只講一件事。** 若同一人回報多件事，會是多列。
- 表單開頭有分流題 `[A2]`：
  - `[A2] = bug` → `[B*]` 欄位有值、`[S*]` 欄位空白
  - `[A2] = idea` → `[S*]` 欄位有值、`[B*]` 欄位空白
  - `[A2] = both` → 兩組都有值
- **空白欄位代表「不適用」，不是「遺漏值」。** 分析時不要當成缺失資料處理。
- 單選/複選欄位的值格式為 `key｜中文說明`（全形直線分隔）。解析時以 `｜` 切開取左半的 `key`。
- 複選欄位（`[S5]`）的多個答案用**半形逗號 + 空格**串接。選項文字本身不含半形逗號。

## 四、分析時的注意事項

### 1. `[B3] = student-told` 的回報，描述經過轉述，可信度較低
小老師是小學生，遇到問題會口頭告訴老師，老師轉述時資訊必然失真。這類回報的 `[B6]`–`[B9]` **不要直接當成事實去追**，先用 `[B12]` + `[B13]` 對 server log 驗證，或回頭問老師。

### 2. `[B11] = data-loss` 一律 P0，不論 `[B10]` 頻率
依 `vision.md` 第 2 節原則四（誠實商店模型）：人為的錯誤（說謊、登錯、填錯）系統不預防、只需可見可補救；但**非人為的技術問題（同步遺失、覆蓋無痕、離線資料損壞、歸屬錯置）系統必須保證不發生**。資料遺失不在誠實商店的豁免範圍內。即使只發生過一次，也要當成最高優先。

### 3. `[S3]` 有具體答案 = 真痛點；`[S3]` 空白或「沒想過」= 想像需求
使用者已經在付出成本繞過某個問題（有 workaround），代表這個需求是真的。沒有 workaround 的建議通常是「想到就講一下」。排優先序時，`[S3]` 有內容的建議應該優先。

### 4. `[S5] = parent-notify` 的勾選數要特別留意
`vision.md` 第 3 節第四點明確寫「不把學生的責任轉移給家長」，系統不應設計讓老師繞過學生直接要求家長處理的功能。這個選項刻意保留在問卷中，是為了測量**現場需求與產品理念之間的落差**。如果勾選率很高，代表：
- (a) 現場老師的需求與本產品的教育理念有實質衝突，或
- (b) 產品沒有把「為什麼不做這個」溝通清楚

兩種可能都值得寫進報告討論，但**不應該直接因為勾選率高就實作**。

### 5. `[B4] + [B5]` 組合可快速分流是否為同步問題

| `[B4]` | `[B5]` | 初判 |
|---|---|---|
| `offline` | `pending` | 正常行為，可能是使用者不理解 → `misunderstanding` |
| `online` | `pending` 持續 | 同步卡住 → 查 `syncController`，004 B4 已知缺口 |
| 任意 | `failed` | 同步失敗出口，004 US1 / FR-081 |
| `unstable` | `synced` 但資料不對 | 疑似 lie-fi，參考 003 FR-075 的 `isServerReachable` 討論 |
| `online` | `none` | 非同步問題，看 `[B1]` 分流 |

### 6. 分類為 `misunderstanding` 的回報，是產品訊號不是雜訊
依 vision 原則三，錯誤或限制發生時，提示要指向**概念**（為什麼），而不只是**行動**（按這裡）。使用者「以為壞了但其實是誤解」代表某個畫面的心智模型沒對上——這正是 vision 主張要修的東西。把這類回報整理成一份清單，是 UI 文案（`src/messages/zh-TW.ts`）的改版依據。
